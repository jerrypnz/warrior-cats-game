# Warrior Cats: Path of the Apprentice

A Godot game made by two kids (with Claude) based on the Warriors books by Erin Hunter. You
design a cat, join ThunderClan and follow the first book's story as the main character, then
keep living in the Clan: patrols, ceremonies, medicine cat work, kits in the nursery, and a
two-player "ThunderClan Together" mode. `history.md` tells the whole story of how it was built.

Grown-ups work on it by running `claude` here. The kids use `./kids-vibe-code`, which adds a
kid-friendly persona (`tools/kids/persona.md`) and kid permissions (`tools/kids/settings.json`)
on top of this file, so everything below applies to both.

## Rules for the game itself

- **Kid-friendly content only**: play-fights with claws sheathed, nobody gets badly hurt, no
  scary horror, no romance, no bad language. This holds whoever asks for the change.
- **The repository is public**: never put a kid's real name, age, school, location or photos
  in any file, commit message or game text.
- **Godot 4 + GDScript only.** The project is in `game/`, made in Godot 4.6
  (`config/features` says 4.3, the minimum it supports).
- **Keep it web-compatible**: the HTML5 build is the main way people play. No `OS.execute()`,
  threads, or file access outside `user://` (saves use `user://`, which is browser storage on
  the web). Keep `variant/thread_support=false` in the Web preset so it runs on plain static
  hosts like GitHub Pages.
- Big, readable text (24px+), controls shown on screen, easy difficulty.

## How the game is put together

- `game/scenes/` holds one scene per place or activity (`title`, `slots`, `creator`, `garden`,
  `camp`, `den`, `hunting`, `patrol`, `duel`, `herbs`, `healing`, `moonstone`, `ceremony`,
  `together`, ...). Each scene is just a root node with a script that builds the rest in code.
- Autoloads (`project.godot`): `GameState` (the player's cat, story progress, save slots and
  friendships), `Sfx`, `Transition`, `PauseMenu`.
- All art is drawn in code with shapes: `cat.gd` draws the chibi cats, `scenery.gd` the
  backgrounds, `herb_art.gd` the herbs, `fx.gd` has particles, floating text and screen shake.
  There are no sprite images.
- Sounds are in `game/assets/sounds/`, generated by `python3 tools/make_sounds.py`. To add a
  sound, add a generator function there; it never overwrites existing files without `--force`.
- Keep scripts simple and readable, nodes descriptively named, scenes saved as `.tscn`.

## Checking your work

Godot exits successfully even when scripts crash, so **never assume a change works**. After
every change run:

```
python3 tools/check_game.py
```

It runs the game for a few seconds and prints `OK` or the errors with file and line. Options:

- `--screenshot` saves `.previews/game.png` to look at (briefly opens a game window). Do this
  after visual changes.
- `--hold move_right --hold jump@1-1.2 --seconds 3` presses input actions during the run;
  tap through the title screen with e.g. `--hold jump@0.5`.
- `--scene res://scenes/camp.tscn` runs one scene.

## Save points and history

- The kids use git as their undo button: after a change passes `check_game.py`, commit it with
  a short, kid-friendly message ("Kits can play moss-ball now").
- To undo, find the save point in `git log` and `git revert` back to it. Never rewrite history
  or throw away commits.
- After each change, add an entry to `history.md`. It's written for the kids:

  ```
  ## Session: YYYY-MM-DD

  ### What the creator asked for:
  [their request, in simple words]

  ### What was built/changed:
  - [changes, in kid-friendly language]

  ### What you can do now:
  - [new things to try]

  ### What's next:
  - [ideas for next time]
  ```

## Sharing the game

`python3 tools/export_game.py` builds self-contained packages for the web, Windows, macOS and
Linux into `dist/` (`--serve` plays the web build at http://localhost:8000). The GitHub
workflows in `.github/workflows/` use it: `pages.yml` publishes the web version on every push,
`release.yml` attaches all packages to a release when a `v*` tag is pushed. See `README.md`.
